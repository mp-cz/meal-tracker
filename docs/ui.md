# UI Coding Standards

These rules apply to all UI code in this project, without exception.

## Core rule: shadcn/ui only

- **Only shadcn/ui components may be used to build the UI.**
- **Do not create custom UI components.** No bespoke buttons, cards, inputs, modals, badges, layouts-as-components, wrappers, or any other reusable visual component.
- If a piece of UI is needed, find the matching shadcn/ui component and use it as-is.
- If no shadcn/ui component fits, compose the UI from existing shadcn/ui components directly in the page. Do not wrap the result in a new component file.

## Adding components

- Install components with the shadcn CLI: `npx shadcn@latest add <component>`.
- Installed components live in `src/components/ui/`. They are generated by the CLI and are the only components allowed in that folder.
- Do not hand-edit generated files in `src/components/ui/` to change their look or behavior. Customize through the props, variants, and `className` that the component already supports at the point of use.
- Check https://ui.shadcn.com/docs/components for the available components before concluding something is missing.

## Composition

- Build pages (`src/app/**/page.tsx`, `layout.tsx`) by composing shadcn/ui components directly.
- Use the component's documented API: its sub-components (e.g. `Card`, `CardHeader`, `CardContent`), variants, and sizes.
- Use `Button`, `Input`, `Label`, `Select`, `Dialog`, `Table`, `Calendar`, `Popover`, etc. rather than raw `<button>`, `<input>`, `<select>`, `<table>` elements.

## Styling

- Style with Tailwind CSS utility classes only (Tailwind v4, configured in `src/app/globals.css`).
- Tailwind classes may be used for layout and spacing (flex, grid, gap, padding, margin) around shadcn/ui components.
- Use the shadcn theme tokens (`bg-background`, `text-foreground`, `text-muted-foreground`, `border`, etc.) rather than hard-coded colors.
- Do not write custom CSS for components. Keep `globals.css` limited to theme variables and base styles.

## Plain HTML

- Plain HTML elements are acceptable only for non-visual structure and text that has no shadcn/ui equivalent, such as `<main>`, `<section>`, `<div>` for layout, and headings/paragraphs, styled with Tailwind classes.
- Never use plain HTML as a substitute for an interactive or visual shadcn/ui component.

## Icons

- Use `lucide-react`, the icon library shadcn/ui uses.

## Checklist before committing UI changes

- [ ] Every visual/interactive element is a shadcn/ui component.
- [ ] No new component files were created outside of the shadcn CLI output.
- [ ] No generated files in `src/components/ui/` were hand-modified.
- [ ] Styling uses Tailwind utilities and theme tokens only.
